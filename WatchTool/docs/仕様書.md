# YouTube配信集計ツール (WatchTool) 仕様書

本ツールは YouTube Data API v3 を使用して特定チャンネルの配信情報を取得し、
デビューからの経過年数（年度）ごとに集計した `result.json` を出力する Kotlin 製 CLI ツールである。

フロントエンド実装者は [6. 出力ファイル仕様](#6-出力ファイル仕様-resultjson) 以降を読めば足りる。

## 1. 概要

### 1.1 目的

- 特定の YouTube チャンネルの全配信（ライブ配信・プレミア公開）を取得する
- 配信の開始予定時刻と実際の開始時刻を比較し、遅刻時間を算出する
- 複数チャンネルの同時配信（コラボ）を 1 つの配信イベントとして集約する
- デビューからの経過年数ごとに配信を区切って出力する

### 1.2 主な機能

| 機能 | 内容 |
|------|------|
| 配信取得 | チャンネルのアップロード済み動画から、終了済みのライブ配信を全件取得 |
| 遅刻算出 | `actualStartTime - scheduledStartTime` を秒単位で算出（負にはならない） |
| セッション集約 | `config.json` の `sessions` で複数動画を 1 配信イベントに束ねる |
| 手動補完 | `config.json` の `overrides` で API から取れない値を上書き・追加 |
| 年度分割 | デビュー記念日を境に「何年目」でグループ化 |
| 出力 | `result.json` 1 ファイル（DeployTool が Cloudflare R2 にアップロード） |

### 1.3 データフロー

```
YouTube Data API v3
        │
        ▼
   WatchTool ──── config/config.json（external / sessions / overrides / debutDate）
        │
        ▼
  result.json
        │
        ▼
   DeployTool ──▶ Cloudflare R2 ──▶ フロントエンド
```

## 3. コマンドライン仕様

```bash
java -jar build/libs/WatchTool-1.0-SNAPSHOT.jar -c <CHANNEL_ID> [オプション]
```

| オプション | 必須 | 既定値 | 説明 |
|-----------|------|-------|------|
| `-c`, `--channel <ID>` | ○ | — | 集計対象チャンネル ID |
| `-o`, `--output <PATH>` | | `output/result.json` | 出力先パス。親ディレクトリは自動作成される |
| `-l`, `--limit <NUM>` | | 無制限 | 取得する配信の最大数（クォータ節約用） |
| `-h`, `--help` | | — | ヘルプ表示 |

**オプションはこの 4 つのみ。** デビュー日・external・sessions・overrides は
すべて `config/config.json` で設定する（→ [4.1](#41-configconfigjson)）。

> `--format` / `--debut-date` / `--start-date` / `--end-date` / `--event-type` / `--verbose` は
> 廃止済み。指定するとオプションエラーで終了する。

### 3.1 使用例

```bash
# 基本（全期間・全件）
java -jar WatchTool.jar -c UCxxxxxxxxxxxxxxxxxxxxxx

# 出力先を指定
java -jar WatchTool.jar -c UCxxxxxxxxxxxxxxxxxxxxxx -o dist/result.json

# 動作確認用に 100 件まで
java -jar WatchTool.jar -c UCxxxxxxxxxxxxxxxxxxxxxx -l 100
```

## 4. 設定ファイル仕様

### 4.1 `config/config.json`

集計内容を制御するメイン設定ファイル。読み込み順は
`config/config.json` → クラスパスの `config.json`（フォールバック）→ 全項目デフォルト。
未知のキーは無視される（`ignoreUnknownKeys = true`）。

```json
{
  "debutDate": "2024-01-13",
  "external": [
    "sPAz3y0XE9Y"
  ],
  "sessions": [
    {
      "id": "tsukapuu24",
      "name": "つかぷー24",
      "videos": ["E5_3ojywJe0", "sPAz3y0XE9Y"]
    }
  ],
  "overrides": [
    {
      "videoId": "S6lQiQDOOGc",
      "delaySeconds": 180
    }
  ]
}
```

| キー | 型 | 既定値 | 説明 |
|------|-----|-------|------|
| `debutDate` | `string?` | `null` | 年度分割の基準日（`YYYY-MM-DD`）。未設定なら年度分割を行わない |
| `external` | `string[]` | `[]` | 他チャンネルの動画 ID。コラボ相手の枠を取得するために使う |
| `sessions` | `SessionConfig[]` | `[]` | 複数動画を 1 配信イベントに束ねる定義 |
| `overrides` | `OverrideConfig[]` | `[]` | 動画単位の値の上書き・手動追加 |

#### SessionConfig

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| `id` | `string` | ○ | 出力 JSON の `AggregateStream.id` になる。videoId と衝突しない値にする |
| `name` | `string` | ○ | 出力 JSON の `AggregateStream.title` になる |
| `videos` | `string[]` | | 束ねる動画 ID。**並び順が primary 動画の選定と年度の帰属を左右する**（→ [6.5](#65-セッションが年度をまたぐ場合)） |

#### OverrideConfig

`videoId` 以外はすべて省略可。省略した項目は API 取得値が保持される。

| キー | 型 | 説明 |
|------|-----|------|
| `videoId` | `string` | 対象動画 ID（必須） |
| `title` | `string?` | タイトル |
| `publishedAt` | `string?` | 公開日時。**空文字を指定した場合は上書きされない** |
| `scheduledStartTime` | `string?` | 配信予定開始時刻（`yyyy-MM-dd HH:mm:ss`、JST） |
| `actualStartTime` | `string?` | 実際の配信開始時刻（同上） |
| `actualEndTime` | `string?` | 配信終了時刻（同上） |
| `viewCount` | `number?` | 視聴回数 |
| `likeCount` | `number?` | 高評価数 |
| `commentCount` | `number?` | コメント数 |
| `delaySeconds` | `number?` | 遅刻時間（秒）。**時刻から再計算されず、この値がそのまま出力される** |
| `streamDurationSeconds` | `number?` | 配信時間（秒）。同様に再計算されない |
| `thumbnail` | `string?` | サムネイル URL（内部保持のみ。出力 JSON には含まれない） |

`overrides` には 2 つの役割がある:

1. **上書き** — API から取得できた動画の値を修正する（遅刻時間の手動補正など）
2. **追加** — API から取得できない動画（削除済み・非公開）を新規に登録する。
   この場合 `external` に含まれていなければ集計対象チャンネルの動画として扱われる。
   指定しなかった項目は空文字 / `0` / `null` になる

### 4.2 `config/config.properties`

API キーと取得挙動の設定。ファイルが存在しない場合はすべて既定値が使われる。

```properties
youtube.api.key=${YOUTUBE_API_KEY}
youtube.api.quota.limit=10000
delay.threshold.minutes=1
```

| キー | 既定値 | 説明 |
|------|-------|------|
| `youtube.api.key` | — | API キー。**環境変数 `YOUTUBE_API_KEY` が優先される** |
| `youtube.api.quota.limit` | `10000` | クォータ上限（超過時は例外） |
| `fetch.max.results` | `50` | 1 ページあたりの取得件数 |
| `fetch.max.videos` | `1000` | 取得上限（現在は CLI `-l` が優先されるため未使用） |
| `delay.threshold.minutes` | `1` | 遅刻判定の閾値（現在は出力に反映されない） |

## 5. 集計処理フロー

[AggregateService.aggregate](../src/main/kotlin/com/github/raink1208/watchtool/service/AggregateService.kt) の処理順。

### 5.1 自チャンネルの動画取得

1. `channels.list(contentDetails)` でアップロードプレイリスト ID を取得
2. `playlistItems.list` で動画 ID を 50 件ずつページネーション取得
3. `videos.list(snippet,liveStreamingDetails,statistics)` で詳細取得
4. ページ間で 500ms の待機を挟む（レート制限対策）

**この段階で除外される動画**（[YouTubeApiClient.kt:117-138](../src/main/kotlin/com/github/raink1208/watchtool/api/YouTubeApiClient.kt#L117-L138)）:

- `liveStreamingDetails` が無い動画 → **通常の投稿動画（非配信）は含まれない**
- `actualEndTime` が無い動画 → **配信中・配信予定の動画は含まれない**

つまり出力対象は原則 **終了済みのライブ配信 / プレミア公開のみ**。
リアルタイムの「今配信中」表示にこのファイルは使えない。

### 5.2 external の動画取得

`config.json` の `external` を 50 件ずつ `videos.list` で取得する。除外条件は 5.1 と同じ。

### 5.3 videoMap 構築

`videoId => Video` の Map を作る。自チャンネル動画 → external の順に格納するため、
同一 ID があれば external 側が優先される。

### 5.4 overrides 適用

`config.json` の `overrides` を videoMap に適用する（→ [4.1](#41-configconfigjson)）。

### 5.5 セッション構築（`linked: true`）

`sessions` ごとに 1 件の `AggregateStream` を生成する。

**primary 動画の選定**（[AggregateService.kt:97-98](../src/main/kotlin/com/github/raink1208/watchtool/service/AggregateService.kt#L97-L98)）:

1. `sessions[].videos` の順に見て、最初に見つかった集計対象チャンネルの動画
2. 該当がなければ `videos` の先頭

**集約ルール**:

| フィールド | 集約方法 |
|-----------|---------|
| `durationSeconds` | 参加動画の**合計**（実時間ではなく延べ配信時間） |
| `viewCount` / `likeCount` / `commentCount` | 参加動画の**合計** |
| `delaySeconds` | **primary 動画の値のみ**（合計しない） |
| `scheduledStartTime` / `actualStartTime` / `actualEndTime` | **primary 動画の値** |

`videos` に書いた動画 ID が videoMap に存在しない場合は警告ログを出してスキップする。

### 5.6 単独配信の抽出（`linked: false`）

videoMap のうち **集計対象チャンネルの動画** かつ **どの `sessions` にも属さないもの** を
1 動画 = 1 配信イベントとして生成する。

`external` の動画は `channelId` が一致しないため、`sessions` に紐付けられない限り出力に現れない。

### 5.7 ソート

セッションと単独配信を結合し、`scheduledStartTime` の**文字列昇順**でソートする。
`yyyy-MM-dd HH:mm:ss` は辞書順＝時系列順。

### 5.8 年度分割

[YearGrouper.group](../src/main/kotlin/com/github/raink1208/watchtool/service/YearGrouper.kt) で
`debutDate` からの経過年数ごとにグループ化する（→ [6.4](#64-年度分割の仕様)）。

## 6. 出力ファイル仕様 (result.json)

| 項目 | 内容 |
|------|------|
| ファイル名 | `result.json`（CLI `-o` で変更可） |
| 文字エンコーディング | UTF-8（BOM なし）。日本語・絵文字はエスケープされず生の UTF-8 |
| 整形 | `prettyPrint = true`（インデント 4 スペース） |
| ルート | 単一の JSON オブジェクト。配信は年度別にネストされている |
| 更新方式 | **差分更新ではなく、毎回全期間の完全なスナップショットとして上書き生成** |

`encodeDefaults = true` のため、**すべてのキーが必ず存在する**（値が `null` でもキーは省略されない）。
`"actualStartTime" in stream` のような存在チェックは不要で、`!== null` で判定する。

### 6.1 トップレベル構造

```json
{
  "debutDate": "2024-01-13",
  "years": [ /* YearGroup の配列 */ ],
  "unknown": [ /* AggregateStream の配列 */ ]
}
```

| フィールド | 型 | null 可 | 説明 |
|-----------|-----|--------|------|
| `debutDate` | `string \| null` | ○ | 年度分割の基準日（`YYYY-MM-DD`）。未設定・パース失敗時は `null` |
| `years` | `YearGroup[]` | × | 年度別グループ。配信が 0 件なら `[]` |
| `unknown` | `AggregateStream[]` | × | `scheduledStartTime` が不明で年度を決められなかった配信。通常は `[]` |

統計値（総配信数・遅刻率・平均遅刻時間など）は **JSON に含まれない**。
フロント側で算出する（→ [8.2](#82-統計値の算出)）。

全配信をフラットに扱う場合は `unknown` を足し忘れないこと:

```ts
const all = [...report.years.flatMap(y => y.streams), ...report.unknown];
```

### 6.2 YearGroup

| フィールド | 型 | null 可 | 説明 |
|-----------|-----|--------|------|
| `index` | `number` | × | **0 起点**の年度番号（`0` = 1年目）。**欠番なく 0 から連番** |
| `label` | `string` | × | 表示用ラベル（`"1年目"`, `"2年目"`, ...）。`debutDate` が `null` なら `"全期間"` |
| `startDate` | `string` | × | グループ開始日（`YYYY-MM-DD`）。`debutDate` が `null` なら空文字 |
| `endDate` | `string` | × | グループ終了日（`YYYY-MM-DD`、**当日を含む**）。`debutDate` が `null` なら空文字 |
| `streams` | `AggregateStream[]` | × | その年度の配信。`scheduledStartTime` 昇順。**配信がない年も空配列で必ず存在する** |

### 6.3 AggregateStream / VideoRef

| フィールド | 型 | null 可 | 説明 |
|-----------|-----|--------|------|
| `id` | `string` | × | 配信イベントの識別子。**YouTube の videoId とは限らない**（→ [6.6](#66-linked-配信イベントの2種類)） |
| `title` | `string` | × | 表示用タイトル。空文字になり得る |
| `durationSeconds` | `number` | × | 配信時間（秒）。0 以上。時刻が欠けている場合は `0` |
| `delaySeconds` | `number` | × | 遅刻時間（秒）。**常に 0 以上**（早く始めても負にならず 0） |
| `viewCount` | `number` | × | 視聴回数 |
| `likeCount` | `number` | × | 高評価数 |
| `commentCount` | `number` | × | コメント数 |
| `scheduledStartTime` | `string` | × | 配信予定開始時刻（JST）。**不明時は `null` ではなく空文字 `""`** |
| `actualStartTime` | `string \| null` | ○ | 実際の配信開始時刻（JST）。不明時は `null` |
| `actualEndTime` | `string \| null` | ○ | 配信終了時刻（JST）。不明時は `null` |
| `linked` | `boolean` | × | `sessions` に紐付けられたコラボ配信かどうか |
| `videos` | `VideoRef[]` | × | 構成動画。通常 1 件以上だが空配列になり得る（→ [6.7](#67-値が欠けるケース)） |

**VideoRef**

| フィールド | 型 | null 可 | 説明 |
|-----------|-----|--------|------|
| `videoId` | `string` | × | YouTube の動画 ID。サムネイル URL の組み立てに使う |
| `title` | `string` | × | その動画自体のタイトル（`AggregateStream.title` とは別物になり得る） |
| `channelId` | `string` | × | 投稿チャンネル ID。コラボ相手のものもあり得る。空文字の場合もある |

### 6.4 年度分割の仕様

区切りは **デビュー記念日基準**（1月1日でも4月1日でもない）。`debutDate` が `2024-01-13` の場合:

| index | label | 期間 |
|-------|-------|------|
| 0 | 1年目 | 2024-01-13 〜 2025-01-12 |
| 1 | 2年目 | 2025-01-13 〜 2026-01-12 |
| 2 | 3年目 | 2026-01-13 〜 2027-01-12 |

**境界の扱い**:

- **デビュー日より前の配信は 1年目（`index: 0`）に含まれる。** 何年前であっても切り捨てられない
- **`scheduledStartTime` がパースできない配信は `unknown` に入る。** どの年度にも重複して現れない
- したがって `years` の全 `streams` と `unknown` の合計 = 全配信数（**重複・欠落なし**）
- 配信が 0 件の年度も `streams: []` で存在するため、`index` は必ず連番になる

**年度分割が行われないケース**:

`debutDate` が未設定、または `YYYY-MM-DD` としてパースできない場合、年度分割は行われず
**全件を含む 1 グループだけ**になる。この場合 `debutDate` は `null`、`label` は `"全期間"`、
`startDate` / `endDate` は空文字、`unknown` は `[]`
（`scheduledStartTime` が空の配信もこのグループに含まれる）。

`report.debutDate === null` で判定できる。年度切り替え UI は隠すのが妥当。

### 6.5 セッションが年度をまたぐ場合

**セッションは分割されず、primary 動画の `scheduledStartTime` が属する年度に 1 件だけ入る。**
複数の年度に複製されることはなく、合計値（`durationSeconds` / `viewCount` / `likeCount` /
`commentCount`）もその年度に全額計上される。

年度判定に使われるのは `AggregateStream.scheduledStartTime`、
つまり **primary 動画の予定開始時刻のみ**。
`videos` に含まれる他の動画がいつ配信されたかは年度判定に影響しない。

例（`debutDate: "2024-01-13"`、記念日 1/13 が境界）:

| セッション構成 | 年度 |
|---|---|
| primary が `2025-01-12 23:00`、コラボ相手の枠が `2025-01-13 01:00` | **1年目のみ**（2年目には現れない） |
| primary が `2025-01-13 01:00`、コラボ相手の枠が `2025-01-12 23:00` | **2年目のみ**（1年目には現れない） |

`actualEndTime` が翌年度に食い込んでいても年度は変わらない（上の例では 1年目のまま）。

**`config.json` の `videos` の並び順が年度の帰属を左右する**（primary の選定順のため）。
記念日をまたぐセッションでは、どちらの年度に入れたいかを `videos` の順序で意図的に決められる。

> ⚠️ primary 動画の `scheduledStartTime` が取得できない（削除済みなど）場合、
> **他の参加動画に有効な時刻があってもセッション全体が `unknown` に入る**。
> `overrides` で primary の `scheduledStartTime` を補完すれば解決する。

### 6.6 `linked`: 配信イベントの2種類

`streams` には性質の異なる 2 種類の要素が混在する。フロント実装で最も注意すべき点。

#### `linked: false` — 単独配信

- `id` === `videos[0].videoId`（YouTube の videoId と一致する）
- `videos.length` === 1
- 各カウント・時間はその動画の値そのまま

#### `linked: true` — セッション（コラボ配信）

- `id` は `sessions[].id`（例 `"tsukapuu24"`）で、**videoId ではない**
- `title` は `sessions[].name`（人間が付けた名前）で、動画タイトルではない
- `videos` に参加した全動画（自チャンネル + コラボ相手）が入る
- 集約ルールは [5.5](#55-セッション構築linked-true) を参照

> ⚠️ `linked: true` の `durationSeconds` は参加人数分だけ積算される。
> 「実際の配信の長さ」を表示したいなら `actualEndTime - actualStartTime` を使うこと。
> 一方で `viewCount` の合算は「コラボ全体の総視聴数」として意味を持つ。
> どちらの意味で見せるかは UI 側の設計判断になる。

### 6.7 値が欠けるケース

以下は異常ではなく正常に出力され得るため、フロント側でガードが必要。

| ケース | 出力 |
|--------|------|
| `overrides` で追加した動画に `title` 未指定 | `title: ""` |
| `overrides` で追加した動画に時刻未指定 | `scheduledStartTime: ""`, `actualStartTime: null` |
| `overrides` で追加した動画に数値未指定 | `viewCount: 0` など |
| `sessions[].videos` の動画がどれも取得できなかった | `videos: []`、各数値 `0`、`scheduledStartTime: ""` |
| `actualEndTime` が `actualStartTime` より前（手動補完ミス） | `durationSeconds: 0`（検証されない） |

### 6.8 重複の可能性

同一 `videoId` を複数の `sessions` に書くと、その動画は複数のセッションに二重計上される。
`config.json` 側の運用で防ぐ想定であり、ツール側での重複排除は行われていない。

`id` は「セッション ID の集合」と「videoId の集合」の合併なので、
両者が衝突しない限りユニーク（React の `key` に使ってよい）。

## 7. 日時フォーマット

すべての時刻フィールドは **JST（Asia/Tokyo）のローカル日時文字列**で、
**タイムゾーン情報を含まない**。

```
yyyy-MM-dd HH:mm:ss     例: "2024-06-27 21:00:00"
```

- ISO 8601 ではない（`T` 区切りでも `Z` / `+09:00` サフィックスでもない）
- 内部では UTC で遅刻時間・配信時間を計算した後、表示用に JST 文字列へ変換して出力している
  （[YouTubeApiClient.kt:144-148](../src/main/kotlin/com/github/raink1208/watchtool/api/YouTubeApiClient.kt#L144-L148)）
- したがって `delaySeconds` / `durationSeconds` はタイムゾーンの影響を受けない正確な秒数

### 7.1 空文字と null の使い分け

| フィールド | 値がない場合 |
|-----------|------------|
| `scheduledStartTime`, `YearGroup.startDate`, `YearGroup.endDate` | `""`（空文字） |
| `actualStartTime`, `actualEndTime`, `debutDate` | `null` |

`if (stream.scheduledStartTime)` のような truthy 判定で両方まとめて扱うのが安全。

### 7.2 JavaScript でのパース

`new Date("2024-06-27 21:00:00")` は**閲覧者のローカルタイムゾーン**として解釈されるため、
JST 以外の環境では時刻がずれる。必ず明示的に `+09:00` を付ける:

```ts
/** "2024-06-27 21:00:00" (JST) -> Date */
function parseJst(s: string | null): Date | null {
  if (!s) return null;                       // null と "" の両方をここで弾く
  const d = new Date(s.replace(" ", "T") + "+09:00");
  return Number.isNaN(d.getTime()) ? null : d;
}
```

JST の年月日・時が欲しいだけなら、`Date` を経由せず文字列を切り出す方が確実
（`scheduledStartTime.slice(0, 7)` で `"2024-06"` など）。
曜日だけは `Date` が必要なので
`parseJst(s)?.toLocaleDateString("ja-JP", { timeZone: "Asia/Tokyo", weekday: "short" })` を使う。

### 7.3 ソート順

- `years` は `index` 昇順（古い年度が先）
- 各 `YearGroup.streams` は `scheduledStartTime` の文字列昇順（古い順）
- `scheduledStartTime` が空文字の配信は `unknown` に分離されるため、
  `years` 内の `streams` には空文字の要素は現れない（`debutDate` が `null` の場合を除く）

新しい順に見せる場合:

```ts
const years   = [...report.years].reverse();       // 年度を新しい順
const streams = [...year.streams].reverse();       // 年度内で新しい順
```

## 8. フロントエンド実装ガイド

### 8.1 TypeScript 型定義

```ts
/** result.json のルート */
export interface AggregateReport {
  /** 年度分割の基準日（YYYY-MM-DD）。未設定・パース失敗時は null */
  debutDate: string | null;
  /** index 0 起点の連番。debutDate が null なら "全期間" の1要素のみ */
  years: YearGroup[];
  /** scheduledStartTime が不明で年度を決められなかった配信 */
  unknown: AggregateStream[];
}

/** デビューから何年目かで区切ったグループ */
export interface YearGroup {
  /** 0 = 1年目。欠番なく 0 から連番 */
  index: number;
  /** 表示用ラベル（"1年目" など）。debutDate が null なら "全期間" */
  label: string;
  /** YYYY-MM-DD。debutDate が null なら空文字 */
  startDate: string;
  /** YYYY-MM-DD（当日を含む）。debutDate が null なら空文字 */
  endDate: string;
  /** scheduledStartTime 昇順。配信がない年も空配列で存在する */
  streams: AggregateStream[];
}

/** 1配信イベント分の集計データ */
export interface AggregateStream {
  /** セッション ID または videoId。linked=false のときのみ videoId と一致 */
  id: string;
  /** 表示用タイトル。空文字になり得る */
  title: string;
  /** 配信時間（秒）。linked=true では参加動画の合計 */
  durationSeconds: number;
  /** 遅刻時間（秒）。常に 0 以上 */
  delaySeconds: number;
  viewCount: number;
  likeCount: number;
  commentCount: number;
  /** JST "yyyy-MM-dd HH:mm:ss"。不明時は空文字 */
  scheduledStartTime: string;
  /** JST "yyyy-MM-dd HH:mm:ss"。不明時は null */
  actualStartTime: string | null;
  /** JST "yyyy-MM-dd HH:mm:ss"。不明時は null */
  actualEndTime: string | null;
  /** config.json の sessions に紐付けられたコラボ配信か */
  linked: boolean;
  /** 構成動画。通常 1 件以上だが空配列になり得る */
  videos: VideoRef[];
}

/** セッション内の各動画への参照 */
export interface VideoRef {
  videoId: string;
  title: string;
  channelId: string;
}
```

数値は Kotlin 側では `Long` だが、実際に扱う値（秒数・視聴回数）は
`Number.MAX_SAFE_INTEGER` を大きく下回るため `number` で安全に扱える。

### 8.2 統計値の算出

年度別に出す場合は `year.streams` を、全期間で出す場合は `years` を flatten して渡す。

```ts
const streams = [...report.years.flatMap(y => y.streams), ...report.unknown];
// 年度別なら: const streams = year.streams;

// 遅刻の判定は delaySeconds > 0
const delayed = streams.filter(s => s.delaySeconds > 0);

const totalStreams = streams.length;
const delayRate    = totalStreams ? (delayed.length / totalStreams) * 100 : 0;

// 平均・最大・最小・中央値は「遅刻した配信のみ」を母数にする
const delays      = delayed.map(s => s.delaySeconds).sort((a, b) => a - b);
const totalDelay  = delays.reduce((a, b) => a + b, 0);
const avgDelay    = delays.length ? totalDelay / delays.length : 0;
const maxDelay    = delays.at(-1) ?? 0;
const minDelay    = delays[0] ?? 0;
const medianDelay = delays.length
  ? (delays.length % 2
      ? delays[(delays.length - 1) / 2]
      : (delays[delays.length / 2 - 1] + delays[delays.length / 2]) / 2)
  : 0;

// 配信時間は durationSeconds > 0 のものを母数にする
const durations     = streams.map(s => s.durationSeconds).filter(d => d > 0);
const totalDuration = durations.reduce((a, b) => a + b, 0);
```

### 8.3 年度別統計

年度分割は WatchTool 側で済んでいるので `years` をそのまま回せばよい。
デビュー日をフロント側の定数として持つ必要もない（`report.debutDate` に入っている）。

```ts
const perYear = report.years.map(year => {
  const delayed = year.streams.filter(s => s.delaySeconds > 0);
  return {
    index:      year.index,
    label:      year.label,
    period:     `${year.startDate} 〜 ${year.endDate}`,
    total:      year.streams.length,
    delayed:    delayed.length,
    delayRate:  year.streams.length ? (delayed.length / year.streams.length) * 100 : 0,
    totalDelay: delayed.reduce((a, s) => a + s.delaySeconds, 0),
  };
});
```

配信がない年度も `streams: []` で存在するため `delayRate` は 0 除算に注意（上記のように件数チェックを入れる）。
折れ線グラフの X 軸に使う場合、空の年度が抜けずに並ぶのでそのまま使える。

### 8.4 月別 / 曜日別 / 時間帯別

```ts
const byMonth = new Map<string, number>();      // "2024-06" -> 件数
for (const s of delayed) {
  if (!s.scheduledStartTime) continue;
  const key = s.scheduledStartTime.slice(0, 7);  // 文字列から直接取るのが最も安全
  byMonth.set(key, (byMonth.get(key) ?? 0) + 1);
}
```

### 8.5 サムネイル URL

`AggregateStream` にサムネイル URL のフィールドは**含まれていない**。videoId から組み立てる:

```
https://i.ytimg.com/vi/{videoId}/sddefault.jpg
```

`linked: true` の場合は自チャンネルの動画を選ぶとよい:

```ts
const thumbVideoId =
  stream.videos.find(v => v.channelId === OWN_CHANNEL_ID)?.videoId
  ?? stream.videos[0]?.videoId;
```

他の解像度も同様に使える（`maxresdefault.jpg` / `hqdefault.jpg` / `mqdefault.jpg`）。
`sddefault` / `maxresdefault` は動画によって存在しないことがあるので `onerror` フォールバックを用意する。

### 8.6 実装チェックリスト

- [ ] 配信は `years[].streams` にネストされている。全件フラットに欲しい場合は
      `years.flatMap(y => y.streams)` に **`unknown` も足す**（足さないと欠落する）
- [ ] `years` は `index` 0 起点の連番。**配信0件の年度も空配列で存在する**（0除算に注意）
- [ ] 年度の境界はデビュー記念日（1/1 でも 4/1 でもない）。`startDate` / `endDate` を表示に使う
- [ ] `debutDate === null` なら年度分割されていない（`"全期間"` の1グループのみ）→ 年度UIを隠す
- [ ] 年度をまたぐセッションも 1 年度にしか入らない。年度別合計の境界がずれ得ることを承知しておく
- [ ] `scheduledStartTime` は空文字、`actualStartTime` / `actualEndTime` は `null` になり得る
- [ ] 日時は JST 固定のタイムゾーンなし文字列。`new Date(s)` を直接使わず `+09:00` を付ける
- [ ] `id` は videoId とは限らない（`linked: true` はセッション ID）。動画リンクは `videos[].videoId` から作る
- [ ] サムネイル URL は JSON に無いので videoId から組み立て、404 のフォールバックを用意する
- [ ] `linked: true` の `durationSeconds` / `viewCount` は参加動画の合計値。表示の意味を決めておく
- [ ] `title` / `videos` が空、各数値が `0` の要素があり得る
- [ ] 統計値は JSON に含まれない。全部フロントで算出する
- [ ] 配信中・配信予定の動画は含まれない（終了済み配信のみ）

## 9. YouTube Data API v3 使用仕様

### 9.1 使用エンドポイント

| エンドポイント | part | 用途 | コスト |
|--------------|------|------|-------|
| `channels.list` | `snippet,statistics` | チャンネル情報の確認（起動時 1 回） | 1 |
| `channels.list` | `contentDetails` | アップロードプレイリスト ID の取得（**ページごと**） | 1 |
| `playlistItems.list` | `contentDetails` | 動画 ID の一覧取得（50 件ずつ） | 1 |
| `videos.list` | `snippet,liveStreamingDetails,statistics` | 動画詳細の取得（50 件ずつ） | 1 |

`search.list`（100 ユニット）は使用していない。

### 9.2 クォータ消費量

1 日のクォータ上限は 10,000 ユニット。実際の消費は概算で:

```
起動時のチャンネル情報          : 1
動画 50 件ごと                  : 3（channels + playlistItems + videos）
external 動画 50 件ごと         : 1
```

例: 1,000 件の配信を持つチャンネルなら `1 + 20 × 3 = 61` ユニット程度。
上限に対して十分余裕があるため、通常は `-l` での制限は不要。

> `channels.list(contentDetails)` がページごとに呼ばれるのは実装上の冗長であり、
> プレイリスト ID をキャッシュすれば 1/3 に削減できる（現状は問題ない規模）。

実行終了時に `使用APIクォータ: Nユニット` が標準出力に表示される。

### 9.3 認証

API キー認証。優先順位は:

1. 環境変数 `YOUTUBE_API_KEY`
2. `config/config.properties` の `youtube.api.key`

どちらも無い場合は `IllegalStateException` で終了する。

## 10. エラーハンドリング

### 10.1 API エラー

| ステータス | 挙動 |
|-----------|------|
| 403 Forbidden | APIキー無効またはクォータ超過。`IllegalStateException` を投げて処理中断 |
| 429 Too Many Requests | 5 秒待機。`VideoFetcher` 側で最大 3 回まで指数バックオフ再試行 |
| 500 / 503 Server Error | 2 秒待機。同様に最大 3 回まで再試行 |
| その他 | エラーログを出して空リストを返す |

`VideoFetcher` は 3 回連続で失敗すると**取得を打ち切ってそこまでの結果を返す**。
そのため API 障害時は配信が欠けた `result.json` が生成され得る点に注意。

### 10.2 データエラー

| ケース | 挙動 |
|--------|------|
| `liveStreamingDetails` が無い | debug ログを出してスキップ（非配信動画） |
| `actualEndTime` が無い | debug ログを出してスキップ（未終了の配信） |
| 動画のパースに失敗 | warn ログを出してその動画のみスキップ |
| `sessions[].videos` の動画が見つからない | warn ログを出してスキップ |
| `debutDate` がパースできない | warn ログを出して年度分割なしにフォールバック |
| 不正な日時フォーマット | `delaySeconds` / `durationSeconds` が `0` になる |

### 10.3 ファイル I/O エラー

| ケース | 挙動 |
|--------|------|
| `config/config.properties` が無い | 既定値を使用（API キーは環境変数から取得） |
| `config/config.json` が無い | クラスパスの `config.json` → 全項目デフォルト |
| 出力先の親ディレクトリが無い | 自動作成する |
| 出力書き込み失敗 | エラーメッセージを表示して終了コード 1 |

| `R2_SECRET_ACCESS_KEY` | ○ | — | R2 シークレットキー |
| `BUCKET_NAME` | | — | R2 バケット名 |
| `REMOTE_PATH` | | — | アップロード先パス |
| `OUTPUT_PATH` | | `/app/output/result.json` | 出力先パス |
| `CRON_SCHEDULE` | | `0 4 * * *` | 実行スケジュール |

**`debutDate` / `external` / `sessions` / `overrides` は環境変数では渡せない。**
`/app/config/config.json` をマウントして設定する。

### 11.3 スケジュール解釈の制限

`entrypoint.sh` は cron 式を厳密に解釈せず、`sleep` による単純ループに変換している:

| 形式 | 解釈 |
|------|------|
| `*/N * * * *` | N 分間隔 |
| `M H * * *` | 24 時間間隔（初回は起動直後、指定時刻ではない） |
| その他 | 1 時間間隔 |

**指定時刻ぴったりに実行されるわけではない**（起動時刻からの相対間隔）。
