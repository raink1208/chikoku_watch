# YouTube配信集計ツール 仕様書

## 1. 概要

本ツールは、YouTube Data API v3を使用して特定のチャンネルの配信情報を取得し、統計データを集計するKotlinベースのコマンドラインツールです。

### 1.1 目的
- 特定のYouTubeチャンネルの全配信（ライブ配信・プレミア公開）を取得
- 配信の開始予定時刻と実際の開始時刻を比較
- 遅刻配信の統計情報を集計・分析

### 1.2 主な機能
- チャンネルIDを指定して配信リストを取得
- 配信の詳細情報（予定時刻、実際の開始時刻、視聴者数など）を取得
- 遅刻配信の検出と集計
- 集計結果のレポート出力（JSON、CSV、テキスト形式）

## 3. 機能仕様

### 3.1 配信情報取得機能

#### 3.1.1 チャンネル検索
- **入力**: チャンネルID または チャンネルハンドル名
- **処理**: YouTube Data API v3の`channels.list`を使用
- **出力**: チャンネル基本情報（名前、説明、登録者数など）

#### 3.1.2 配信リスト取得
- **入力**: チャンネルID
- **API使用**: `search.list` + `videos.list`
- **取得条件**:
  - タイプ: video
  - eventType: completed, live, upcoming
  - order: date (日付順)
- **ページネーション**: 最大50件ずつ、全件取得まで繰り返し
- **出力**: 配信動画のリスト

#### 3.1.3 配信詳細情報取得
各配信について以下の情報を取得:
- 動画ID
- タイトル
- 説明文
- 公開日時
- 配信予定開始時刻 (`liveStreamingDetails.scheduledStartTime`)
- 実際の配信開始時刻 (`liveStreamingDetails.actualStartTime`)
- 配信終了時刻 (`liveStreamingDetails.actualEndTime`)
- 同時視聴者数（ピーク）(`liveStreamingDetails.concurrentViewers`)
- 総視聴回数 (`statistics.viewCount`)
- 高評価数 (`statistics.likeCount`)
- コメント数 (`statistics.commentCount`)

### 3.2 遅刻分析機能

#### 3.2.1 遅刻判定
- **判定条件**: `actualStartTime` - `scheduledStartTime` > 0
- **遅刻時間計算**: 分単位で算出
- **分類**:
  - 定刻開始: 0分
  - 軽微な遅刻: 1-5分
  - 通常遅刻: 6-15分
  - 大幅遅刻: 16-30分
  - 深刻な遅刻: 31分以上

#### 3.2.2 統計計算
- 総配信数
- 遅刻配信数
- 遅刻率（%）
- 平均遅刻時間
- 最大遅刻時間
- 最小遅刻時間
- 遅刻時間の中央値
- 遅刻分類別の配信数
- 月別遅刻統計
- 曜日別遅刻統計
- 時間帯別遅刻統計

## 4. YouTube Data API v3 使用仕様

### 4.1 必要なAPIエンドポイント

#### 4.1.1 channels.list
```
GET https://www.googleapis.com/youtube/v3/channels
パラメータ:
  - part: snippet,statistics
  - id: チャンネルID
  - key: APIキー
```

#### 4.1.2 search.list
```
GET https://www.googleapis.com/youtube/v3/search
パラメータ:
  - part: snippet
  - channelId: チャンネルID
  - type: video
  - eventType: completed (または live, upcoming)
  - order: date
  - maxResults: 50
  - pageToken: ページネーション用トークン
  - key: APIキー
```

#### 4.1.3 videos.list
```
GET https://www.googleapis.com/youtube/v3/videos
パラメータ:
  - part: snippet,liveStreamingDetails,statistics
  - id: 動画ID（カンマ区切りで最大50件）
  - key: APIキー
```

### 4.2 APIクォータ管理
- 1日のクォータ上限: 10,000ユニット
- 各APIのコスト:
  - channels.list: 1ユニット
  - search.list: 100ユニット
  - videos.list: 1ユニット
- クォータ超過を防ぐための取得件数制限機能を実装

### 4.3 認証
- APIキー認証方式を使用
- APIキーは設定ファイルまたは環境変数から読み込み
- `config/api_config.properties` または環境変数 `YOUTUBE_API_KEY`

## 5. 設定ファイル仕様

### 5.1 api_config.properties
```properties
# YouTube API設定
youtube.api.key=YOUR_API_KEY_HERE
youtube.api.quota.limit=10000

# 取得設定
fetch.max.results=50
fetch.enable.pagination=true
fetch.max.videos=1000

# 遅刻判定設定
delay.threshold.minutes=1
```

### 5.2 channels.json
監視対象チャンネルのリスト
```json
{
  "channels": [
    {
      "id": "UCxxxxx",
      "name": "チャンネル名",
      "enabled": true
    }
  ]
}
```

## 6. コマンドライン引数仕様

### 6.1 基本使用法
```bash
java -jar WatchTool.jar [オプション]
```

### 6.2 オプション
- `-c, --channel <CHANNEL_ID>`: 対象チャンネルID（必須）
- `-o, --output <PATH>`: 出力ファイルパス（デフォルト: output/result.json）
- `-f, --format <FORMAT>`: 出力形式（json/csv/text、デフォルト: json）
- `-l, --limit <NUM>`: 取得する配信の最大数（デフォルト: 全件）
- `-s, --start-date <DATE>`: 取得開始日（YYYY-MM-DD形式）
- `-e, --end-date <DATE>`: 取得終了日（YYYY-MM-DD形式）
- `--event-type <TYPE>`: 配信タイプ（completed/live/upcoming、デフォルト: completed）
- `-v, --verbose`: 詳細ログ出力
- `-h, --help`: ヘルプ表示

### 6.3 使用例
```bash
# 基本的な使用
java -jar WatchTool.jar -c UCxxxxx

# CSV形式で出力
java -jar WatchTool.jar -c UCxxxxx -f csv -o result.csv

# 期間指定で取得
java -jar WatchTool.jar -c UCxxxxx -s 2025-01-01 -e 2025-03-31

# 最大100件まで取得
java -jar WatchTool.jar -c UCxxxxx -l 100
```

## 7. エラーハンドリング

### 7.1 APIエラー
- 403 Forbidden: APIキーが無効、またはクォータ超過
  - 対応: エラーメッセージ表示、処理中断
- 404 Not Found: チャンネルまたは動画が見つからない
  - 対応: 警告ログ出力、スキップして続行
- 429 Too Many Requests: レート制限
  - 対応: 指数バックオフで再試行（最大3回）
- 500/503 Server Error: YouTube API側のエラー
  - 対応: リトライ処理（最大3回）

### 7.2 データエラー
- `scheduledStartTime`または`actualStartTime`が存在しない
  - 対応: 該当配信を遅刻分析から除外、ログ出力
- 不正な日時フォーマット
  - 対応: エラーログ出力、該当データをスキップ

### 7.3 ファイルI/Oエラー
- 設定ファイル読み込み失敗
  - 対応: デフォルト値使用、警告表示
- 出力ファイル書き込み失敗
  - 対応: エラーメッセージ表示、処理中断

## 8. パフォーマンス要件

### 8.1 処理速度
- 100件の配信データ取得: 約10-30秒以内
- 統計計算処理: 1秒以内

### 8.2 メモリ使用量
- 最大ヒープサイズ: 512MB以内

### 8.3 並行処理
- API呼び出しの並行実行（最大5スレッド）
- レート制限遵守のための制御機構
