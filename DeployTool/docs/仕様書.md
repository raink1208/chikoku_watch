# ファイル監視・自動アップロードツール 仕様書

## 1. 概要

特定のファイルパスを監視し、ファイルの変更を検知してCloudflare R2ストレージなどのクラウドストレージに自動的にアップロードするツールです。

## 2. 目的

- 指定されたファイルの変更を検知し、自動的にクラウドストレージにアップロードする
- 差分検知により、不要なアップロードを防ぎ、効率的な運用を実現する
- 複数のストレージプロバイダーに対応できる拡張性を持つ

## 3. 主要機能

### 3.1 ファイル監視機能

- **監視対象**: 設定ファイルで指定された1つ以上のファイルパス
- **実行方法**: 
  - JAR実行時に一度だけチェックを実行
  - 実行時にファイルの内容を確認し、前回実行時からの変更を検知
  - 定期実行が必要な場合は、cron/タスクスケジューラなどの外部ツールで制御

### 3.2 変更検知機能

- **検知方法**: ファイルのハッシュ値（SHA-256など）を計算し比較
- **状態管理**: 
  - 前回実行時のハッシュ値をローカルに保存（`.deploy-state.json`など）
  - ファイルパスごとにハッシュ値と最終アップロード日時を記録
- **変更判定**: 
  - 現在のハッシュ値と保存されたハッシュ値を比較
  - 変更がない場合はアップロードをスキップ
  - 初回実行時は必ずアップロード

### 3.3 アップロード機能

#### 3.3.1 対応ストレージプロバイダー

**Phase 1（初期実装）:**
- Cloudflare R2

**Phase 2（将来対応予定）:**
- Amazon S3
- Google Cloud Storage
- Azure Blob Storage
- その他のS3互換ストレージ

#### 3.3.2 アップロード仕様

- **認証**: 各ストレージプロバイダーの認証情報を設定ファイルから読み込み
- **アップロード先パス**: 設定により柔軟に指定可能
- **エラーハンドリング**: 
  - ネットワークエラー時のリトライ機能（最大3回）
  - アップロード失敗時のログ記録
- **並列処理**: 複数ファイルの場合、並列でアップロード可能

## 4. 設定ファイル仕様

### 4.1 設定ファイル形式

**ファイル名**: `config.properties`

**形式**: Java Properties形式

**例**:

```properties
# 状態管理ファイル
state.file=.deploy-state.json

# アップロード対象ファイル（カンマ区切りで複数指定可能）
files.count=2

files.0.local_path=/path/to/file1.txt
files.0.remote_path=uploads/file1.txt
files.0.enabled=true

files.1.local_path=/path/to/file2.json
files.1.remote_path=data/file2.json
files.1.enabled=true

# ストレージプロバイダー設定
storage.provider=cloudflare-r2

# Cloudflare R2設定
storage.cloudflare_r2.account_id=${CLOUDFLARE_ACCOUNT_ID}
storage.cloudflare_r2.access_key_id=${R2_ACCESS_KEY_ID}
storage.cloudflare_r2.secret_access_key=${R2_SECRET_ACCESS_KEY}
storage.cloudflare_r2.bucket_name=my-bucket
storage.cloudflare_r2.endpoint=https://${CLOUDFLARE_ACCOUNT_ID}.r2.cloudflarestorage.com

# 将来の拡張用（コメントアウト例）
# storage.aws_s3.access_key_id=${AWS_ACCESS_KEY_ID}
# storage.aws_s3.secret_access_key=${AWS_SECRET_ACCESS_KEY}
# storage.aws_s3.bucket_name=my-s3-bucket
# storage.aws_s3.region=us-east-1

# ログ設定
logging.level=INFO
logging.file=logs/deploy-tool.log
logging.console=true

# リトライ設定
retry.max_attempts=3
retry.initial_delay_ms=1000
retry.max_delay_ms=10000
retry.multiplier=2.0
```

### 4.2 環境変数

機密情報は環境変数から読み込むことを推奨:
- `CLOUDFLARE_ACCOUNT_ID`: CloudflareアカウントID
- `R2_ACCESS_KEY_ID`: R2アクセスキーID
- `R2_SECRET_ACCESS_KEY`: R2シークレットアクセスキー

### 4.3 設定項目の詳細

#### ファイル設定
- `files.count`: 監視対象ファイルの数
- `files.{n}.local_path`: ローカルファイルパス
- `files.{n}.remote_path`: リモート（アップロード先）パス
- `files.{n}.enabled`: 有効/無効フラグ

#### ストレージ設定
- `storage.provider`: 使用するストレージプロバイダー（`cloudflare-r2`, `aws-s3`, `gcs`など）
- `storage.{provider}.{param}`: 各プロバイダー固有のパラメータ

#### ログ設定
- `logging.level`: ログレベル（`DEBUG`, `INFO`, `WARN`, `ERROR`）
- `logging.file`: ログファイルパス
- `logging.console`: コンソール出力の有効/無効

#### リトライ設定
- `retry.max_attempts`: 最大リトライ回数
- `retry.initial_delay_ms`: 初回リトライ待機時間（ミリ秒）
- `retry.max_delay_ms`: 最大リトライ待機時間（ミリ秒）
- `retry.multiplier`: リトライ待機時間の倍率

## 5. 状態管理ファイル仕様

### 5.1 ファイル形式

**ファイル名**: `.deploy-state.json`

**形式**: JSON

**例**:

```json
{
  "version": "1.0",
  "last_updated": "2025-10-19T02:17:00Z",
  "files": {
    "/path/to/file1.txt": {
      "hash": "sha256:a1b2c3d4e5f6...",
      "last_upload": "2025-10-19T02:15:00Z",
      "size": 1024,
      "status": "success"
    },
    "/path/to/file2.json": {
      "hash": "sha256:f6e5d4c3b2a1...",
      "last_upload": "2025-10-19T02:16:00Z",
      "size": 2048,
      "status": "success"
    }
  }
}
```

### 5.2 フィールド説明

- `version`: 状態ファイルのバージョン
- `last_updated`: 最終更新日時
- `files`: ファイルごとの状態情報
  - `hash`: ファイルのSHA-256ハッシュ値
  - `last_upload`: 最終アップロード日時
  - `size`: ファイルサイズ（バイト）
  - `status`: 最終実行結果（success, failed, skipped）

## 6. アーキテクチャ設計

### 6.1 コンポーネント構成

```
┌─────────────────────────────────────────────┐
│           Main Application                  │
│  - 設定読み込み                              │
│  - 実行制御                                  │
└─────────────────┬───────────────────────────┘
                  │
        ┌─────────┴─────────┐
        │                   │
┌───────▼────────┐  ┌──────▼──────────┐
│ FileWatcher    │  │ StateManager    │
│ - ファイル監視  │  │ - 状態管理       │
│ - 変更検知      │  │ - ハッシュ計算   │
└───────┬────────┘  └──────┬──────────┘
        │                   │
        └─────────┬─────────┘
                  │
        ┌─────────▼─────────┐
        │ StorageUploader   │
        │ - インターフェース │
        └─────────┬─────────┘
                  │
        ┌─────────┴─────────┐
        │                   │
┌───────▼────────┐  ┌──────▼──────────┐
│ R2Uploader     │  │ (Future)        │
│ - R2実装        │  │ - S3Uploader    │
└────────────────┘  │ - GCSUploader   │
                    └─────────────────┘
```

### 6.2 主要クラス

#### 6.2.1 Config
- **責務**: 設定ファイルの読み込みと管理
- **主要メソッド**:
  - `load(path: String): Config`
  - `validate(): Boolean`

#### 6.2.2 StateManager
- **責務**: ファイル状態の管理とハッシュ計算
- **主要メソッド**:
  - `loadState(): FileState`
  - `saveState(state: FileState)`
  - `calculateHash(filePath: String): String`
  - `hasChanged(filePath: String): Boolean`

#### 6.2.3 FileWatcher
- **責務**: ファイル監視と変更検知
- **主要メソッド**:
  - `watch(files: List<WatchTarget>)`
  - `checkChanges(): List<ChangedFile>`

#### 6.2.4 StorageUploader（インターフェース）
- **責務**: ストレージアップロードの抽象化
- **主要メソッド**:
  - `upload(localPath: String, remotePath: String): UploadResult`
  - `validate(): Boolean`

#### 6.2.5 R2Uploader
- **責務**: Cloudflare R2への実装
- **継承**: StorageUploader
- **依存**: AWS SDK for S3（R2はS3互換API）

## 7. 実行フロー

### 7.1 通常実行フロー

```
1. 設定ファイルの読み込み
   ↓
2. 状態ファイルの読み込み
   ↓
3. 各監視対象ファイルについて:
   ├─ ファイルの存在確認
   ├─ ハッシュ値の計算
   ├─ 前回ハッシュ値と比較
   └─ 変更あり？
      ├─ Yes → アップロード実行
      │         ├─ 成功 → 状態更新
      │         └─ 失敗 → リトライ → ログ記録
      └─ No  → スキップ（ログ記録）
   ↓
4. 状態ファイルの保存
   ↓
5. 実行結果のサマリー表示
```

### 7.2 エラーハンドリング

- **ファイルが存在しない**: WARNログを出力、スキップ
- **ハッシュ計算失敗**: ERRORログを出力、スキップ
- **アップロード失敗**: リトライ → 失敗時はERRORログ、状態は更新しない
- **設定ファイル不正**: アプリケーション終了

## 8. ログ出力仕様

### 8.1 ログレベル

- **DEBUG**: 詳細なデバッグ情報（ハッシュ値、API呼び出し詳細など）
- **INFO**: 通常の実行情報（開始、完了、スキップ、アップロード成功）
- **WARN**: 警告（ファイル未存在、設定の問題など）
- **ERROR**: エラー（アップロード失敗、致命的エラー）

## 9. 依存ライブラリ

### 9.1 必須ライブラリ

- **AWS SDK for Kotlin (S3)**: Cloudflare R2との通信（S3互換API）
- **kotlinx-serialization-json**: JSON設定ファイルの解析（状態ファイル用）
- **kotlinx-coroutines**: 非同期処理、並列アップロード
- **slf4j / logback**: ログ出力

### 9.2 推奨ライブラリ

- **clikt**: CLIインターフェース構築
- **kotlin-result**: エラーハンドリング

### 9.3 備考

- Propertiesファイルの読み込みはKotlin/Java標準ライブラリの`java.util.Properties`を使用
- 環境変数の置換は独自実装または`org.apache.commons:commons-text`の`StringSubstitutor`を使用

## 10. コマンドライン仕様

### 10.1 基本コマンド

```bash
# 通常実行（デフォルト設定ファイル使用）
java -jar deploy-tool.jar

# 設定ファイル指定
java -jar deploy-tool.jar --config /path/to/config.properties

# ドライラン（アップロードせず変更検知のみ）
java -jar deploy-tool.jar --dry-run

# 強制アップロード（変更検知をスキップ）
java -jar deploy-tool.jar --force

# 特定ファイルのみ実行
java -jar deploy-tool.jar --file /path/to/file1.txt

# バージョン表示
java -jar deploy-tool.jar --version

# ヘルプ表示
java -jar deploy-tool.jar --help
```

### 10.2 オプション

| オプション | 短縮形 | 説明 | デフォルト |
|----------|--------|------|-----------|
| `--config` | `-c` | 設定ファイルのパス | `config.properties` |
| `--dry-run` | `-n` | ドライラン実行 | false |
| `--force` | `-f` | 強制アップロード | false |
| `--file` | - | 特定ファイルのみ処理 | すべて |
| `--verbose` | `-v` | 詳細ログ出力 | false |
| `--version` | `-V` | バージョン表示 | - |
| `--help` | `-h` | ヘルプ表示 | - |

## 11. セキュリティ考慮事項

### 11.1 認証情報の管理

- 認証情報は環境変数から読み込むことを推奨
- 設定ファイルに平文で保存しない
- `.gitignore`に状態ファイルと設定ファイルを追加

### 11.2 ファイルアクセス権限

- 状態ファイルは適切なパーミッション（600）で保存
- 設定ファイルの読み取り権限を確認

### 11.3 通信のセキュリティ

- HTTPS/TLSを使用した暗号化通信
- 証明書の検証を必ず実施

## 14. パフォーマンス要件

- 1ファイルあたりのハッシュ計算: 100MB/秒以上
- 同時アップロード: 最大5ファイル並列
- メモリ使用量: 256MB以下（通常運用時）

## 15. 運用要件

### 15.3 監視・運用

- ログファイルのローテーション設定
